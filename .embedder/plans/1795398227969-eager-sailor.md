# Prune unused BSP modules only

## Outcome

Remove unused board-support and component-driver modules under `Drivers/BSP` for the active LGT92 STM32L072 + SX1276MB1LAS firmware. Leave `Drivers/CMSIS` and `Drivers/STM32L0xx_HAL_Driver` completely untouched.

## Recommended approach

1. **Preserve active and conditional BSP dependencies.** Keep the nine Components used by the root CMake target (`flash_eraseprogram`, `gpio_exti`, `gps`, `iwdg`, `IIC`, `filter`, `mpu9250`, `sx1276`, `usart`), `STM32L0xx_Nucleo`, and `sx1276mb1las` ([`CMakeLists.txt`](../../CMakeLists.txt#L29-L39)). Also retain `B-L072Z-LRWAN1` and `MLM32L07X01`, because the kept `USE_B_L072Z_LRWAN1` branch in [`hw_conf.h`](../../Projects/Multi/Applications/LoRa/DRAGINO-LRWAN\(AT\)/inc/hw_conf.h#L78-L83) references that board configuration.

2. **Remove unused alternate BSPs.** Delete `I_NUCLEO_LRWAN1`, `LRWAN_NS1`, `MDM32L07X01`, `STM32L1xx_Nucleo`, `STM32L4xx_Nucleo`, `sx1272mb2das`, `sx1276mb1mas`, `X_NUCLEO_IKS01A1`, and `X_NUCLEO_IKS01A2`. Their component dependencies are only needed by those alternate BSPs or are otherwise unreferenced by retained source/configuration.

3. **Remove unused BSP Components and orphaned shared sensor interfaces.** Delete `bh1750`, `ds18b20`, `hts221`, `lidar_lite_v3hp`, `lis3mdl`, `lps22hb`, `lps25hb`, `lsm303agr`, `lsm6ds0`, `lsm6ds3`, `lsm6dsl`, `oil_float`, `pwr_out`, `sht20`, `sht31`, `sx1272`, `tfmini_plus`, `ult`, `weight`, and `Common`. Keep the nine active component directories. `Common` becomes unused after removal of the X-NUCLEO/LoRa sensor BSPs and their high-level sensor drivers; remove its include path from root [`CMakeLists.txt`](../../CMakeLists.txt#L83-L105) as a minimal build-manifest cleanup.

4. **Remove dangling documentation references only.** Update root [`Release_Notes.html`](../../Release_Notes.html#L57-L101) to drop links for deleted BSP directories. Do not modify application sources, HAL, CMSIS, or any other driver folders.

## Validation

* Search retained source/configuration and all remaining `Drivers/BSP` files for references to each deleted path/header; resolve any remaining reference by retaining the needed module rather than broadening the cleanup.

* Configure and build in a separate fresh directory (for example, `cmake -S . -B build/drivers-cleanup -DCMAKE_TOOLCHAIN_FILE=cmake/arm-none-eabi-gcc.cmake`, then `cmake --build build/drivers-cleanup`) so existing outputs are preserved. Require `lgt92.elf` and `lgt92.hex`, and confirm the map/source list remains the STM32L072 + SX1276MB1LAS + EU868 target.

* Review the diff to verify changes are limited to `Drivers/BSP` plus the stated minimal CMake include-path and release-note updates. Confirm CMSIS and HAL trees are unchanged; do not flash hardware.
